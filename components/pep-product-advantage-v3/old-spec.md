# pep-product-advantage-v2 组件核心能力分析报告

## 核心能力概述

`pep-product-advantage-v2` 是一个基于 Xtemplate 和 jQuery 开发的产品优势展示楼层组件，主要用于展示产品特性和优势信息。该组件支持多种布局模式、响应式设计和丰富的交互功能，适用于企业官网产品介绍页面。

## 一、核心功能要求

### 1.1 核心功能定义

**组件核心用途**：展示产品优势信息，通过卡片式布局呈现产品特性、描述和操作按钮。

**不可缺失的核心功能点**：
- 楼层标题和副标题展示
- 多行多列卡片布局支持
- 卡片内容折叠/展开交互（移动端）
- 图片懒加载功能
- 多端链接适配
- 响应式布局适配

### 1.2 业务逻辑映射

**业务场景与逻辑处理**：

| 业务场景 | 逻辑处理规则 | 对应功能点 |
|---------|-------------|-----------|
| 产品优势展示 | 根据配置数据动态渲染卡片内容 | 数据驱动渲染 |
| 移动端交互 | 自动展开第一个卡片，支持手动折叠/展开 | 折叠交互逻辑 |
| 多端适配 | 根据设备类型调整布局和交互方式 | 响应式适配 |
| 链接跳转 | 支持外部链接跳转，自动适配多端环境 | 链接处理逻辑 |

### 1.3 用户交互能力

**支持的用户操作**：
- **点击操作**：移动端卡片标题点击触发折叠/展开
- **链接跳转**：按钮点击跳转到指定页面
- **滚动加载**：图片懒加载，提升页面性能

**交互反馈要求**：
- 折叠/展开状态切换动画
- 按钮悬停状态变化
- 图片加载占位效果

## 二、布局与展示要求

### 2.1 基础布局规范

**整体布局结构**：
```
楼层容器 (pep-product-advantage-v2)
├── 楼层头部 (por-section-head)
│   ├── 标题 (por-section-title)
│   └── 副标题 (por-section-subtitle)
└── 楼层主体 (por-section-body)
    └── 卡片行 (por-row)
        └── 卡片列 (por-col-*)
            └── 卡片容器 (por-card)
                ├── 卡片内容 (card-content)
                │   ├── 卡片标题 (card-title)
                │   ├── 描述列表 (lists)
                │   └── 按钮组 (card-btn)
                └── 卡片图片 (card-image)
```

**核心展示元素位置约束**：
- 标题：楼层顶部，字体加粗
- 卡片：网格布局，支持 1-4 列排列
- 图片：根据列宽自适应尺寸
- 按钮：卡片底部，水平排列

### 2.2 响应式适配要求

**设备类型适配**：

| 设备类型 | 屏幕范围 | 布局调整规则 |
|---------|---------|-------------|
| PC端 | >1600px | 完整布局，大字体大间距 |
| 中等屏幕 | 1280px-1600px | 缩小字体和间距 |
| 小屏幕 | 769px-1280px | 进一步缩小字体间距 |
| 移动端 | ≤768px | 单列布局，启用折叠交互 |

**布局调整规则**：
- PC端：支持多列布局，图片和内容并排显示
- 移动端：强制单列布局，图片和内容垂直排列
- 字体大小：28px → 22px → 18px → 14px
- 间距调整：48px → 40px → 32px → 20px

### 2.3 展示状态覆盖

**所有展示状态及UI表现**：

| 状态类型 | 触发条件 | UI表现 |
|---------|---------|--------|
| 默认状态 | 页面加载完成 | 卡片正常显示，PC端全部展开 |
| 加载状态 | 图片懒加载 | 显示占位，图片渐入效果 |
| 折叠状态 | 移动端用户操作 | 隐藏卡片内容，显示标题和箭头 |
| 展开状态 | 移动端用户操作 | 显示完整卡片内容 |
| 空数据状态 | 数据为空 | 需要兜底处理（当前未实现） |

## 三、数据流与状态管理

### 3.1 数据输入要求

**输入数据格式**：
```typescript
interface ComponentData {
  baseInfo: {
    theme: 'light' | 'grey';     // 楼层背景主题
    title: string;               // 楼层标题
    subtitle?: string;           // 楼层副标题（支持HTML）
  };
  cardItemLists: Array<{
    layout: 1 | 2 | 3 | 4;      // 布局模式（1列、2列12:12、2列14:10、2列10:14）
    cardItem: Array<{
      cardTitle: string;         // 卡片标题
      bgImage: string;           // 背景图片URL
      cardInfos: Array<{         // 描述信息列表
        showLICircle: boolean;   // 是否显示圆点符号
        description: string;     // 描述内容（支持HTML）
      }>;
      btnLists?: Array<{         // 按钮列表（可选）
        btnType: string;         // 按钮样式类型
        btnText: string;         // 按钮文字
        btnLink: string;         // 按钮链接
      }>;
    }>;
  }>;
}
```

**必填项及默认值**：
- `baseInfo.theme`: 默认 'light'
- `baseInfo.title`: 必填
- `cardItemLists[].layout`: 默认 2
- `cardItemLists[].cardItem[].cardTitle`: 必填
- `cardItemLists[].cardItem[].bgImage`: 必填
- `cardItemLists[].cardItem[].cardInfos`: 必填，至少1项

### 3.2 数据处理流程

**核心数据处理步骤**：

1. **数据接收**：从外部接收配置数据
2. **布局计算**：根据 layout 值计算栅格系统
   ```javascript
   porColArray = {
     '1': [24],      // 一列布局
     '2': [12, 12],  // 两列等宽
     '3': [14, 10],  // 两列14:10
     '4': [10, 14]   // 两列10:14
   }
   ```
3. **模板渲染**：Xtemplate 模板引擎渲染HTML
4. **图片处理**：懒加载和链接格式化
5. **交互初始化**：绑定事件和初始化状态

### 3.3 数据输出规范

**输出形式**：
- **事件触发**：折叠/展开交互触发DOM事件
- **链接跳转**：按钮点击触发页面跳转
- **数据回传**：当前无数据回传需求

**输出数据格式**：
- 链接跳转：通过 `href` 属性直接跳转
- 交互状态：通过CSS类名控制显示状态

### 3.4 状态管理要求

**核心状态维护**：

| 状态类型 | 初始值 | 变更条件 | 联动逻辑 |
|---------|--------|---------|---------|
| 折叠状态 | PC端全部展开，移动端第一个展开 | 用户点击触发 | 切换显示/隐藏内容 |
| 懒加载状态 | 未加载 | 图片进入视口 | 触发图片加载 |
| 链接状态 | 未处理 | 页面加载完成 | 自动扫描并替换链接 |

## 四、异常处理规范

### 4.1 异常场景覆盖

**需处理的异常场景**：
- 输入数据格式错误
- 图片加载失败
- 链接格式错误
- 网络请求失败（懒加载）
- 用户操作异常

### 4.2 异常处理规则

**各异常场景处理逻辑**：

| 异常场景 | 处理逻辑 | 兜底方案 |
|---------|---------|---------|
| 数据格式错误 | 数据校验，跳过无效字段 | 使用默认值 |
| 图片加载失败 | 显示错误占位图 | 当前未实现 |
| 链接格式错误 | 链接格式化处理 | 保持原链接 |
| 网络请求失败 | 重试机制 | 显示默认图片 |

### 4.3 错误反馈要求

**用户反馈形式**：
- **图片加载失败**：显示错误占位图（需实现）
- **数据错误**：静默处理，不影响其他内容
- **链接错误**：浏览器默认错误处理

**反馈文案要求**：
- 错误信息应简洁明了
- 提供明确的解决方案或替代方案

## 五、重写与迁移要点

### 5.1 重点关注标识

**🔥 重点关注要点**：

1. **布局系统复杂性**：支持4种不同的栅格布局模式，需要精确计算
2. **响应式适配**：多断点适配，特别是移动端的折叠交互
3. **图片懒加载**：性能优化关键点，需要正确处理加载时机
4. **多端链接处理**：确保链接在不同环境下正确跳转
5. **国际化支持**：阿拉伯语等RTL语言的布局适配

### 5.2 适配迁移需求

**与上下游模块对接要求**：

| 对接模块 | 输入参数兼容性 | 输出兼容性 | 事件机制兼容性 |
|---------|---------------|-----------|---------------|
| 数据源 | 完全兼容现有JSON格式 | 无输出要求 | 无事件要求 |
| 样式系统 | 兼容现有CSS变量 | 无输出要求 | 无事件要求 |
| 图片服务 | 兼容现有图片URL格式 | 无输出要求 | 无事件要求 |

**迁移后集成要求**：
- 保持现有API接口不变
- 确保样式类名兼容性
- 维护现有交互行为
- 支持现有配置数据格式

### 5.3 重写技术建议

**技术栈选择建议**：
- **框架选择**：Vue 3 + TypeScript（推荐）
- **状态管理**：Pinia 或 Composition API
- **样式方案**：CSS Modules + CSS Variables
- **构建工具**：Vite 或 Webpack 5

**实现优先级**：
1. 核心布局和样式实现
2. 数据驱动渲染
3. 响应式适配
4. 交互功能实现
5. 性能优化和异常处理

**测试覆盖要求**：
- 单元测试：核心逻辑函数
- 集成测试：组件渲染和交互
- 视觉回归测试：多断点布局
- 性能测试：图片懒加载效果
