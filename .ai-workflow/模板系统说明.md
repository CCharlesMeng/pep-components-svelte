# 模板系统重构说明

## 🎯 重构目标

从"代码生成"转为"模板拷贝"，确保生成的组件 **100% 可运行**。

---

## 📊 变更对比

### ❌ 之前的方式（代码生成）

```python
# scaffold_component.py
def _template_minimal_component(self) -> str:
    return f"""<script lang="ts">
  export let className = '';
</script>
..."""
```

**问题**：
- ❌ 可能有语法错误
- ❌ 配置文件可能不完整
- ❌ 依赖版本可能不对
- ❌ 生成的组件可能无法立即运行

---

### ✅ 现在的方式（模板拷贝）

```python
# scaffold_component.py
def generate(self):
    # 1. 拷贝整个模板目录
    shutil.copytree(TEMPLATE_DIR, self.component_dir)
    
    # 2. 替换占位符
    self._replace_placeholders_in_directory()
    
    # 3. 重命名文件
    self._rename_placeholder_files()
```

**优势**：
- ✅ **保证能运行**（模板本身就能运行）
- ✅ **配置完整**（所有必需文件都有）
- ✅ **依赖一致**（与现有组件一致）
- ✅ **易于维护**（更新模板即可）

## 📝 占位符规则

| 占位符 | 替换为 | 示例 |
|--------|--------|------|
| `{{COMPONENT_NAME}}` | 组件名称（kebab-case）| `pep-my-component` |
| `{{COMPONENT_NAME_PASCAL}}` | 组件名称（PascalCase）| `PepMyComponent` |
| `{{DESCRIPTION}}` | 组件描述 | "我的组件" |
| `{{INIT_DATE}}` | 初始化时间 | `2025-12-18T10:30:00Z` |

**示例**：

模板文件 `src/{{COMPONENT_NAME}}.svelte`:
```svelte
<div class="{{COMPONENT_NAME}}">
  <slot>组件内容</slot>
</div>
```

生成后 `src/pep-my-component.svelte`:
```svelte
<div class="pep-my-component">
  <slot>组件内容</slot>
</div>
```

## 🎯 设计理念

### 1. "零组件"概念

`templates/component/` 就是一个"零组件"：
- ✅ 它本身就是可运行的
- ✅ 包含最小但完整的结构
- ✅ 所有配置文件都齐全
- ✅ 依赖版本与项目一致

### 2. 渐进增强

```
最小模板（可运行）
    ↓
用户完善 spec.md
    ↓
AI 生成 features.json
    ↓
用户逐步实现功能
```

**核心**：先保证能运行，再逐步增强。

### 3. 单一模板原则

- ❌ 不需要多套模板（minimal、standard、custom）
- ✅ 一个标准模板就够了
- 原因：简单可靠，易于维护

### 4. 模板即文档

`templates/component/` 本身就是组件结构的最佳文档：
- 新人可以直接查看模板
- 理解组件应该有哪些文件
- 理解每个文件的作用

## 🔧 维护指南

### 更新模板

如果需要更新所有新组件的默认结构：

```bash
# 1. 修改模板
vim .ai-workflow/templates/component/package.json

# 2. 测试模板（可选）
cp -r .ai-workflow/templates/component /tmp/test
cd /tmp/test
# 手动替换占位符
pnpm install
pnpm dev

# 3. 完成！新组件会自动使用最新模板
```

### 添加新占位符

如果需要添加新的占位符：

```python
# 1. 在模板中使用新占位符
# templates/component/package.json
"author": "{{AUTHOR_NAME}}"

# 2. 更新脚本
# scripts/scaffold_component.py
def _generate_placeholders(self):
    return {
        ...
        '{{AUTHOR_NAME}}': self.data.get('author', 'PEP Team'),
    }

# 3. 更新文档
# templates/README.md 添加新占位符说明
```

## 🎉 总结

### 核心改进

1. **稳定性提升**：从"代码生成"到"模板拷贝"，100% 保证可运行
2. **维护性提升**：更新模板即可，无需修改生成逻辑
3. **一致性提升**：所有组件结构完全一致
4. **可测试性提升**：模板本身可以测试

### 用户收益

- ✅ `/pep-start` 生成的组件**一定能运行**
- ✅ 不会遇到"生成的代码有语法错误"的问题
- ✅ 配置文件完整，不需要手动补充
- ✅ 可以立即 `pnpm dev` 看到效果

### 开发者收益

- ✅ 脚本逻辑更简单（拷贝+替换 vs 复杂的代码生成）
- ✅ 更容易维护（模板文件 vs Python 字符串拼接）
- ✅ 更容易测试（直接测试模板 vs 测试生成逻辑）
- ✅ 更容易扩展（修改模板 vs 修改生成代码）
