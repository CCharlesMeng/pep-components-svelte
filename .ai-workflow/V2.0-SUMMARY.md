## 1️⃣ 会话状态管理优化 ✅

### 问题
> 原有的 `.component-dev/` 目录下的 `current_prompt.md` 和 `session_state.json` 并不会被自动初始化，且这两个文件的作用并不明确，需求的开发是多轮的，应当参考 spec-kit 或 open-spec 的方式，外层只保留当前一次的任务描述，已完成的任务需要进行归档。

### 解决方案

#### 新的目录结构
```
components/pep-button/
├── .cursor-session/              # 当前会话（简洁）
│   ├── current-task.md          # 仅保留当前任务
│   └── session-history.json     # 简要历史记录
│
├── .cursor-archive/              # 已完成任务归档（新增）
│   ├── 20231218-121530-001-基础组件结构.md
│   ├── 20231218-143022-002-Props接口定义.md
│   └── ...
│
└── .cursor-prompts/              # AI提示词（按需）
    └── generate-features.md
```

#### 工作流程
1. **当前任务**: `pep-dev next` 生成 `current-task.md`
2. **开发过程**: 只关注 `current-task.md`
3. **任务完成**: `pep-dev done` 自动归档并清理
4. **历史追溯**: 在 `.cursor-archive/` 查看所有已完成任务

#### 归档示例
```markdown
# pep-button - 基础组件结构

## 基本信息
- **功能ID**: 1
- **完成时间**: 2023-12-18T12:15:30
- **提交哈希**: abc123d
- **是否测试**: 是

## 功能描述
创建 pep-button 组件的基础文件结构...

## 验收标准
1. ✅ 组件文件已创建且无TypeScript错误
2. ✅ TypeScript类型定义完整
...

---
*归档时间: 2023-12-18 12:15:30*
```

## 2️⃣ Spec-First 开发流程 ✅

### 问题
> features.json 的生成，不应当默认提供手工修改的方式，应该引导用户通过一份 spec.md 的编写，再与 cursor 沟通自动生成 features.json

### 解决方案

#### 强制 Spec-First 流程

**步骤1: 编写 spec.md**
```markdown
# pep-button 组件规格

## 概述
可复用的按钮组件，支持多种样式和状态

## 功能需求

### 1. Props 接口
- `variant`: 'primary' | 'secondary' | 'danger'
- `size`: 'small' | 'medium' | 'large'
- `disabled`: boolean
- `loading`: boolean

### 2. 事件
- `click`: 点击事件
- `focus`: 聚焦事件
...

### 3. 样式要求
- 支持主题定制
- 响应式设计
- 无障碍友好
...
```

**步骤2: 自动生成 features.json**
```bash
# 初始化（检查是否有 spec.md）
pep-dev init pep-button

# 如果没有 spec.md，会提示：
# ❌ 错误: 未找到 spec.md 规格文档
# 
# 请按以下步骤操作:
#   1. 创建规格文档: vim components/pep-button/spec.md
#   2. 重新运行初始化

# 有 spec.md 后，生成 AI 提示词
pep-dev spec pep-button

# 在 Cursor 中使用 AI 生成 features.json
```

**步骤3: AI 生成精确的功能清单**

AI 会根据 spec.md 生成包含以下内容的 features.json：
- 详细的功能描述
- 具体的验收标准
- 合理的依赖关系
- 准确的优先级和复杂度

#### 核心文件

**scripts/init-component.js** - 修改为强制检查 spec.md：
```python
# 检查 spec.md 是否存在
spec_file = component_dir / "spec.md"
if not spec_file.exists():
    print("❌ 错误: 未找到 spec.md 规格文档")
    print("请先创建规格文档...")
    return
```

**scripts/generate-spec.js** - 新增，专门从 spec.md 生成 features.json

## 4️⃣ 统一命令行工具 ✅

### 问题
> 整个工作流的使用还是以人工衔接为主，需要提炼一套 command，可以内含 python 脚本的执行命令，这套 command 支持用户进行直接使用。

### 解决方案

#### 统一 CLI 工具: `pep-dev`

**安装**:
```bash
# 方式1: 软链接（推荐）
sudo ln -s /path/to/cursor-autonomous-coding/pep-dev /usr/local/bin/pep-dev

# 方式2: alias
alias pep-dev='/path/to/cursor-autonomous-coding/pep-dev'

# 验证
pep-dev help
```

**核心命令**:
```bash
pep-dev <command> <component> [options]

命令列表:
  init <component>          初始化组件
  spec <component>          生成 features.json
  next <component>          获取下一个任务
  done <component> <id>     完成任务并归档
  validate <component>      验证功能清单
  check <component>         合规性检查
  rules <component>         全局规则检查
  status <component>        查看进度
  summary                   整体进度
```

#### 完整工作流（全自动化）

```bash
# === 初始化阶段 ===
vim components/pep-button/spec.md     # 编写规格
pep-dev init pep-button               # 初始化
pep-dev spec pep-button               # 生成功能清单
pep-dev validate pep-button           # 验证
pep-dev check pep-button              # 合规检查

# === 开发循环 ===
pep-dev next pep-button --save        # 获取任务
# ... 在 Cursor 中开发 ...
pep-dev done pep-button 1 --tested   # 完成并归档

pep-dev next pep-button --save        # 下一个任务
# ... 开发 ...
pep-dev done pep-button 2 --tested   # 完成并归档

# === 进度跟踪 ===
pep-dev status pep-button             # 单个组件进度
pep-dev summary                       # 整体进度
```

#### 核心文件

**pep-dev** - 统一入口：
```python
#!/usr/bin/env python3
"""PEP Components 开发命令行工具"""

COMMANDS = {
    "init": {"script": "init-component.js", ...},
    "spec": {"script": "generate-spec.js", ...},
    "next": {"script": "next-task.js", ...},
    "done": {"script": "mark-done.js", ...},
    "validate": {"script": "validate.js", ...},
    "check": {"script": "check-compliance.js", ...},
    "rules": {"script": "validate-global-rules.js", ...},
    "status": {"script": "report.js", ...},
    "summary": {"script": "monorepo-summary.js", ...},
}

def run_command(command, args):
    script_path = SCRIPT_DIR / COMMANDS[command]["script"]
    subprocess.run([sys.executable, str(script_path)] + args)
```
