# Monorepo单组件开发完整指南

本指南详细说明如何在Monorepo中开发单个组件，使用规范化的 spec → features → 开发 → 归档流程。

---

## 🎯 核心理念

### Spec-First 开发
1. **编写规格文档** (`spec.md`) - 明确需求和设计
2. **AI生成功能清单** (`features.json`) - 从规格自动生成任务
3. **Cursor迭代开发** - 使用AI辅助开发
4. **自动验证归档** - 完成后自动归档和验证

### 多轮任务管理
- **当前任务**: `.cursor-session/current-task.md` - 仅保留当前正在开发的任务
- **已完成任务**: `.cursor-archive/` - 已完成任务自动归档
- **会话历史**: `.cursor-session/session-history.json` - 完整开发历史

---

## 🚀 完整开发流程

### 第0步：配置 pep-dev 命令

将 `pep-dev` 命令添加到 PATH（一次性配置）：

```bash
# 方式1: 创建软链接（推荐）
sudo ln -s /path/to/pep-components-svelte/cursor-autonomous-coding/pep-dev /usr/local/bin/pep-dev

# 方式2: 添加alias到 ~/.zshrc 或 ~/.bashrc
alias pep-dev='/path/to/pep-components-svelte/cursor-autonomous-coding/pep-dev'

# 验证
pep-dev help
```

---

### 第1步：创建规格文档 ⭐

**重要**: 必须先编写 `spec.md` 规格文档

```bash
cd components/pep-common-banner

# 创建规格文档
vim spec.md
```

**spec.md 模板**：

```markdown
# pep-common-banner 组件规格

## 概述
通用 Banner 组件，用于显示重要通知、警告或信息提示。

## 设计目标
- 支持多种类型（info、warning、error、success）
- 可自定义样式和图标
- 支持关闭按钮
- 响应式设计
- 无障碍友好

## 功能需求

### 1. Props 接口
- `type`: 'info' | 'warning' | 'error' | 'success'
- `message`: string（主要消息内容）
- `closable`: boolean（是否可关闭）
- `icon`: string | Component（自定义图标）
- `duration`: number | null（自动关闭时间）

### 2. 事件
- `close`: 用户点击关闭按钮时触发
- `afterClose`: Banner 完全关闭后触发

### 3. 样式要求
- 支持主题色彩
- 支持亮色/暗色模式
- 支持自定义背景色

### 4. 无障碍要求
- 支持键盘导航
- 提供 ARIA 标签
- 支持屏幕阅读器

## 示例用法

\`\`\`svelte
<Banner
  type="warning"
  message="系统将在 10 分钟后维护"
  closable={true}
  duration={5000}
  on:close={handleClose}
/>
\`\`\`

## 技术栈
- Svelte 4+
- TypeScript
- CSS Modules / SCSS
```

**💡 提示**: 使用 Cursor AI 帮助编写 spec.md

```
在 Cursor Chat 中:
"帮我编写 pep-common-banner 组件的规格文档，包括概述、Props、事件、样式要求、无障碍要求"
```

---

### 第2步：初始化组件并生成功能清单

```bash
# 在 monorepo 根目录
cd /path/to/pep-components-svelte

# 初始化组件（检查spec.md并生成AI提示词）
pep-dev init pep-common-banner

# 输出示例：
# ✓ spec.md 读取成功 (1200 字符)
# ✓ AI 提示词已保存到: components/pep-common-banner/.cursor-prompts/generate-features.md
# 
# 📋 下一步：使用 pep-dev spec 命令生成 features.json
```

---

### 第3步：生成 features.json

**方式1: 使用命令（推荐）⭐**

```bash
pep-dev spec pep-common-banner
```

这将：
1. 读取 `spec.md`
2. 生成 AI 提示词
3. 引导你在 Cursor 中生成 `features.json`

**方式2: 手动操作**

1. 打开 `.cursor-prompts/generate-features.md`
2. 在 Cursor 中使用 Composer (Cmd+I) 或 Chat (Cmd+L)
3. 粘贴提示词
4. 将 AI 生成的 JSON 保存到 `features.json`

---

### 第4步：验证和合规检查

```bash
# 验证功能清单结构
pep-dev validate pep-common-banner

# 检查组件合规性（技术栈、架构、规范）
pep-dev check pep-common-banner

# 检查全局规则
pep-dev rules pep-common-banner
```

**合规性检查包括**：
- ✅ 必需文件是否存在
- ✅ spec.md 与 features.json 一致性
- ✅ 技术栈一致性
- ✅ 架构规范
- ✅ 文档完整性

---

## ❓ 常见问题

### Q1: 必须先写 spec.md 吗？

**是的！** Spec-First 是推荐的开发方式：
- 明确需求和设计
- AI 可以生成更准确的功能清单
- 减少返工和变更

### Q2: features.json 可以手动编写吗？

**不推荐。** 应该通过 spec.md + AI 生成：
- 更准确、更详细
- 验收标准更具体
- 节省时间

### Q3: 归档的任务可以删除吗？

**不建议删除。** 归档是为了：
- 历史追溯
- 知识积累
- 审计和合规

如果空间有限，可以定期备份到其他存储。

### Q4: 如何与团队协作？

每个组件独立开发：
```bash
# 你负责 pep-button
git checkout -b feature/pep-button
pep-dev next pep-button --save

# 同事负责 pep-modal
git checkout -b feature/pep-modal
pep-dev next pep-modal --save
```

### Q5: current-task.md 被覆盖了怎么办？

不用担心！已完成的任务会归档到 `.cursor-archive/`：
```bash
# 查看归档
ls .cursor-archive/

# 恢复某个任务的信息
cat .cursor-archive/20231218-121530-001-基础组件结构.md
```
