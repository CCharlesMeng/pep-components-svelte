# v1.2 新功能快速参考

## 📜 功能1：全局规则系统

### 什么是全局规则？
在monorepo根目录统一管理所有组件必须遵循的规范，确保100+组件的一致性。

### 核心文件
- `global-rules.json` - 规则配置文件
- `validate-global-rules.js` - 验证脚本

### 快速开始

```bash
# 验证单个组件
node scripts/validate-global-rules.js \
  --component pep-button

# 验证所有组件
node scripts/validate-global-rules.js \
  --all

# 自动修复问题
node scripts/validate-global-rules.js \
  --component pep-button \
  --fix
```

### 验证内容
- ✅ 组件命名规范（如：必须以`pep-`开头）
- ✅ 必需文件（README.md、features.json等）
- ✅ 文档完整性（必需章节）
- ✅ Git分支命名
- ✅ 功能清单质量

### 典型工作流

```bash
# 1. 初始化组件
node scripts/init-component.js --component pep-button

# 2. 立即验证并修复
node scripts/validate-global-rules.js --component pep-button --fix

# 3. 开始开发
node scripts/next-task.js --component pep-button --save

# 4. 开发中...

# 5. 完成前再次验证
node scripts/validate-global-rules.js --component pep-button --strict

# 6. 标记完成
node scripts/mark-done.js --component pep-button --feature-id 1
```

### 自定义规则

编辑 `global-rules.json`:

```json
{
  "custom_rules": {
    "my_rule": {
      "description": "我的规则",
      "required": true
    }
  }
}
```

## 🤖 功能2：全自动化模式

### 什么是全自动化模式？
自动循环执行开发任务，减少手动输入命令的次数，但仍需要在Cursor中手动编码。

### 工作原理
```
获取任务 → 生成提示词 → 等待你在Cursor开发 → 测试 → 提交 → 下一个
    ↑                                                              ↓
    └──────────────────── 自动循环 ────────────────────────────────┘
```

### 快速开始

```bash
# 基础用法（最安全）
node scripts/auto-develop.js \
  --component pep-button

# 限制迭代次数
node scripts/auto-develop.js \
  --component pep-button \
  --max-iterations 3

# 启用自动测试
node scripts/auto-develop.js \
  --component pep-button \
  --auto-test
```

### 使用流程

1. **启动脚本**
   ```bash
   node scripts/auto-develop.js --component pep-button
   ```

2. **脚本自动获取任务并生成提示词**
   ```
   ✨ 下一个任务: 功能 #1 - pep-button 基础结构
   ✓ 提示词已保存: .component-dev/current-task.md
   ```

3. **在Cursor中开发**
   - 打开Cursor Composer
   - 引用 `@current-task.md`
   - 让AI帮你完成

4. **回答问题**
   ```
   ✅ 功能开发完成了吗？ (y/N): y
   🧪 测试通过了吗？ (y/N): y
   📝 代码已提交了吗？ (y/N): y
   ```

5. **自动循环到下一个任务**

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--component` | 组件名称 | `--component pep-button` |
| `--max-iterations` | 最大迭代次数 | `--max-iterations 5` |
| `--delay` | 每次迭代延迟（秒） | `--delay 30` |
| `--auto-test` | 自动运行测试 | `--auto-test` |
| `--auto-commit` | 自动提交（危险！） | `--auto-commit` |
| `--cursor-prompt-only` | 只生成提示词 | `--cursor-prompt-only` |

### 使用场景

**场景1：专注开发日**
```bash
# 一整天专注开发一个组件
node scripts/auto-develop.js --component pep-button
# 按Ctrl+C暂停，明天继续运行相同命令
```

**场景2：快速原型**
```bash
# 只完成核心功能
node scripts/auto-develop.js \
  --component pep-button \
  --max-iterations 5 \
  --auto-test
```

**场景3：批量组件**
```bash
# 依次完成多个小组件
for comp in pep-icon pep-badge pep-tag; do
    node scripts/auto-develop.js --component $comp --max-iterations 10
done
```

### 安全建议

✅ **推荐**:
- 从小开始（`--max-iterations 3`）
- 不使用 `--auto-commit`（手动review）
- 使用 `--auto-test` 确保质量

⚠️ **谨慎**:
- `--auto-commit` 需要充分信任AI
- 定期检查代码质量
- 每5个功能验证一次全局规则

## 💡 最佳实践速查

### ✅ 推荐做法

1. **初始化时就验证**
   ```bash
   node scripts/init-component.js --component XXX
   node scripts/validate-global-rules.js --component XXX --fix
   ```

2. **使用自动模式但保留审查**
   ```bash
   node scripts/auto-develop.js --component XXX --auto-test
   # 不使用 --auto-commit，手动review后提交
   ```

3. **定期全局检查**
   ```bash
   # 每周运行
   node scripts/validate-global-rules.js --all > weekly-report.log
   ```

4. **批次开发，批次验证**
   ```bash
   # 完成5个功能，验证一次
   node scripts/auto-develop.js --component XXX --max-iterations 5
   node scripts/validate-global-rules.js --component XXX --strict
   ```

### ❌ 避免做法

1. ❌ 跳过全局规则验证直接开发
2. ❌ 使用 `--auto-commit` 而不review代码
3. ❌ 忽略验证警告
4. ❌ 长时间无人值守运行自动模式

## 🆘 常见问题

### Q1: 全局规则验证失败怎么办？
```bash
# 查看详细错误
node scripts/validate-global-rules.js --component XXX

# 自动修复简单问题
node scripts/validate-global-rules.js --component XXX --fix

# 手动修复后重新验证
node scripts/validate-global-rules.js --component XXX --strict
```

### Q2: 自动模式可以完全无人值守吗？
❌ 不可以。你仍需要：
- 在Cursor中编写代码
- 审查AI生成的代码
- 确认功能已完成
- 最好手动review后再提交

### Q3: 可以自定义规则吗？
✅ 可以。编辑 `global-rules.json` 并扩展验证脚本。

### Q4: 如何暂停自动模式？
按 `Ctrl+C` 随时停止。重新运行相同命令继续。
