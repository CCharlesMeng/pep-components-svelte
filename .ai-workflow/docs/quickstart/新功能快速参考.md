# V2.0 新功能快速参考

## 🎯 核心变更一览

### 1. 统一 CLI 工具 `pep-dev`

**旧方式** (V1.0):
```bash
python3 cursor-autonomous-coding/scripts/next_task.py --component pep-button
```

**新方式** (V2.0):
```bash
pep-dev next pep-button --save
```

**改进**: 命令简洁 60-70%

### 2. Spec-First 工作流

**旧方式**: 手动编写 features.json
```bash
vim features.json  # 手动填写任务
```

**新方式**: AI 从 spec.md 生成
```bash
vim spec.md        # 编写规格
pep-dev spec       # AI 生成 features.json
```

**改进**: 更准确、更完整的任务清单

### 3. 自动归档系统

**旧方式**: 多文件混乱
```
.component-dev/
├── current_prompt.md
├── session_state.json
└── ...（用途不明）
```

**新方式**: 清晰归档
```
.cursor-session/
├── current-task.md     # 仅当前任务

.cursor-archive/
├── 20250108-001-xxx.md # 已完成归档
└── ...
```

**改进**: 历史清晰可追溯

### 4. 自动合规检查

**新增功能**:
```bash
pep-dev validate  # 格式验证
pep-dev check     # 合规检查
pep-dev rules     # 全局规则检查
```

**改进**: 自动保证代码质量

## 🚀 新工作流速查

### 开发新组件

```bash
# 1. 编写规格
vim components/pep-button/spec.md

# 2. 初始化
pep-dev init pep-button

# 3. 生成任务
pep-dev spec pep-button

# 4. 验证
pep-dev validate pep-button
pep-dev check pep-button

# 5. 开发循环
pep-dev next pep-button --save
# ... 开发 ...
pep-dev done pep-button 1 --tested
```

### 继续开发现有组件

```bash
# 获取下一个任务
pep-dev next pep-button --save

# 在 Cursor 中开发
# ...

# 完成并归档
pep-dev done pep-button 2 --tested
```

### 进度查看

```bash
# 单个组件进度
pep-dev status pep-button

# 整体进度
pep-dev summary
```

## 💡 快速技巧

### 技巧 1: 跳过问题

初始化时可以跳过问题：
```bash
# 在交互式问答中输入
skip
# 或使用快速模式
pep-dev init pep-button --quick
```

### 技巧 2: 批量操作

```bash
# 验证所有组件
for comp in components/pep-*/; do
  pep-dev validate $(basename $comp)
done
```

### 技巧 3: 查看归档

```bash
# 查看已完成的任务
ls components/pep-button/.cursor-archive/

# 查看某个归档
cat components/pep-button/.cursor-archive/20250108-001-xxx.md
```

### 技巧 4: 合并模式

重新生成 features.json 时使用合并模式：
```bash
pep-dev spec pep-button
# AI 会询问：重新生成 or 合并？
# 选择 merge 保留已完成的任务
```

## ⚠️ 常见陷阱

### 陷阱 1: 忘记写 spec.md

```bash
# ❌ 错误
pep-dev init pep-button  # 会报错：找不到 spec.md

# ✅ 正确
vim components/pep-button/spec.md  # 先写规格
pep-dev init pep-button
```

### 陷阱 2: 直接编辑 features.json

```bash
# ❌ 不推荐
vim features.json  # V2.0 不推荐手动编辑

# ✅ 推荐
vim spec.md              # 修改规格
pep-dev spec pep-button  # 重新生成
```

### 陷阱 3: 忘记 --save

```bash
# ❌ 只是查看，不保存
pep-dev next pep-button

# ✅ 保存到 current-task.md
pep-dev next pep-button --save
```

### 陷阱 4: 跳过验证

```bash
# ❌ 跳过验证
pep-dev spec pep-button
pep-dev next pep-button  # 直接开发

# ✅ 先验证
pep-dev spec pep-button
pep-dev validate pep-button  # 验证格式
pep-dev check pep-button     # 验证合规
pep-dev next pep-button      # 再开发
```

## 🎓 进阶用法

### 自定义验证规则

编辑 `project-config.json`：
```json
{
  "tech_stack": {
    "framework": "Svelte",
    "language": "TypeScript"
  },
  "required_files": [
    "README.md",
    "spec.md",
    "features.json"
  ]
}
```

### 查看详细日志

```bash
# 使用 --verbose 标志
pep-dev check pep-button --verbose
```

### 导出进度报告

```bash
# 生成 HTML 报告
pep-dev status pep-button --format html > report.html

# 生成 Markdown 报告
pep-dev status pep-button --format markdown > report.md
```
