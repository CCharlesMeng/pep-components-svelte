# PEP Spec - 需求规格澄清

## 🎯 职责

通过对话式交互，澄清和完善组件的需求规格（spec.md）。

**核心目标**：
1. 识别 spec.md 中不清晰、缺失、模糊的部分
2. 通过智能对话收集完整需求
3. 增量更新 spec.md
4. 确保需求清晰、全面、无歧义

**下一步**：运行 `/pep-plan` 生成开发任务

---

## 📋 执行流程

### 阶段 0: 前置检查

```markdown
1. 检查组件是否存在
   components/<component-name>/ 不存在
   → 提示：请先运行 /pep-start 创建组件

2. 检查 spec.md 是否存在
   spec.md 不存在
   → 提示：文件缺失，请先运行 /pep-start

3. 读取当前 spec.md 内容
   → 进入【阶段 1：分析 spec 质量】
```

### 阶段 1: 分析 spec.md 质量

#### Agent 行为指令

```markdown
读取 spec.md，分析以下维度：

1. 概述是否清晰？
   - 只有占位符 → 缺失
   - 一句话简述 → 基本
   - 详细说明 → 完整

2. 核心功能是否具体？
   - 空或模板内容 → 缺失
   - 功能列表但无细节 → 不完整
   - 详细描述 + 子功能点 → 完整

3. Props 设计是否明确？
   - 空或只有示例 → 缺失
   - 有列表但无说明 → 不完整
   - 完整表格 + 类型 + 默认值 → 完整

4. 验收标准是否具体？
   - 空或通用模板 → 缺失
   - 有清单但不具体 → 不完整
   - 详细可测试的标准 → 完整

5. 特殊需求章节
   - 样式要求、事件设计、无障碍等

基于分析结果，判断 spec 质量：
- 高质量（80%+ 完整）→ 进入【阶段 2A：微调模式】
- 中等质量（50-80%）→ 进入【阶段 2B：补充模式】
- 低质量（< 50%）→ 进入【阶段 2C：重构模式】
```

## 🎯 关键设计原则

### 1. 智能推断优先
- 基于组件类型和常见模式推断设计
- 展示推断结果，用户只需确认或纠正
- 比逐项询问效率高很多

### 2. 分层对话策略
```
spec 质量 → 对话轮次

高质量（80%+）
  → 0-1 轮（只问需不需要补充细节）

中等质量（50-80%）
  → 2-4 轮（补充关键缺失项）

低质量（< 50%）
  → 建议重新开始，或深度对话 5-8 轮
```

### 3. 灵活退出机制
- 用户可随时回复 'skip' / '够了' / '就这样'
- Agent 立即停止询问，保存已收集信息
- 基于已有信息尽力完善 spec
- 标注推断的部分（如 "<!-- AI 推断，请确认 -->"）

### 4. 增量更新
- 不覆盖用户已有内容
- 只补充缺失部分
- 合并新旧内容
- 保持 spec 结构完整

## 📤 更新策略

### spec.md 增量更新规则

```markdown
1. 读取当前 spec.md 全文

2. 解析章节结构
   ## 概述
   ## 核心功能
   ## Props 设计
   ...

3. 对每个需要更新的章节：
   
   【如果章节不存在】
   → 追加新章节到适当位置
   
   【如果章节存在但内容为空/模板】
   → 填充新内容
   
   【如果章节存在且有用户内容】
   → 合并内容：
     • Props 表格：追加新行，不删除现有行
     • 功能列表：追加新项，保留现有项
     • 验收标准：追加新标准，保留现有标准

4. 使用 search_replace 或 write 工具更新文件
```

### 示例：Props 章节合并

**原有内容**：
```markdown
## Props 设计

| Prop | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| className | string | '' | 自定义类名 |
```

**新增内容**：
```markdown
| variant | 'primary' | 'secondary' | 'primary' | 按钮变体 |
| size | 'small' | 'medium' | 'large' | 'medium' | 按钮尺寸 |
```

**合并结果**：
```markdown

| Prop | 类型 | 默认值 | 说明 |
|------|------|--------|------|
```

## ⚠️  注意事项

1. **不要过度询问**
   - 优先使用智能推断
   - 最多 1-2 轮确认
   - 低质量 spec 才深度对话

2. **保存用户进度**
   - 支持中途退出
   - 已收集的信息不丢失
   - 允许分多次完善

3. **增量更新**
   - 永远不要删除用户已有内容
   - 只追加或合并
   - 冲突时提示用户选择

4. **明确引导**
   - 完成后告诉用户下一步
   - 推荐运行 /pep-plan
   - 说明 spec 的作用
