# Monorepo单组件开发完整指南

本指南详细说明如何在Monorepo中开发单个组件，适用于100+组件的大型项目。

---

## 🎯 适用场景

- ✅ pnpm/yarn/npm workspaces项目
- ✅ 100+独立组件
- ✅ 每个组件由不同人维护
- ✅ 组件独立开发、独立分支
- ✅ 需要统一的开发流程

---

## 📂 组件目录结构

```
pep-components-svelte/
├── components/
│   ├── pep-common-banner/         # 你负责的组件
│   │   ├── src/                   # 组件源码
│   │   ├── package.json           # 组件依赖
│   │   ├── README.md              # 组件文档
│   │   ├── features.json          # ⭐ 功能清单
│   │   ├── DEVELOPMENT.md         # ⭐ 开发日志
│   │   └── .component-dev/        # ⭐ 会话状态
│   │       ├── current_prompt.md  # 当前任务提示词
│   │       └── session_state.json # 会话状态
│   │
│   ├── pep-button/                # 其他人维护
│   ├── pep-modal/                 # 其他人维护
│   └── ... (100+ 组件)
│
├── cursor-autonomous-coding/      # 开发工具
└── pnpm-workspace.yaml
```

## 🚀 完整开发流程

### 步骤1: 初始化组件

```bash
# 在monorepo根目录
cd /path/to/pep-components-svelte

# 初始化组件（首次）
python3 cursor-autonomous-coding/scripts/init_component.py \
  --component pep-common-banner

# 生成的文件
# ✅ features.json - 功能清单
# ✅ DEVELOPMENT.md - 开发日志
# ✅ .component-dev/ - 会话状态目录
```

**初始化后需要手动编辑 `features.json`**，定义组件的功能清单。

---

### 步骤2: 编写功能清单

编辑 `components/pep-common-banner/features.json`:

```json
{
  "project": {
    "name": "pep-common-banner",
    "description": "通用Banner组件",
    "version": "1.0.0"
  },
  "features": [
    {
      "id": 1,
      "name": "基础组件结构",
      "description": "创建Svelte组件基础结构，包含props定义和基本样式",
      "status": "pending",
      "priority": "high",
      "category": "core",
      "estimated_hours": 2,
      "dependencies": [],
      "test_criteria": [
        "组件可以被导入",
        "接受type、title、message props",
        "渲染正确的HTML结构"
      ],
      "acceptance_criteria": [
        "代码通过TypeScript检查",
        "组件可正常导出"
      ]
    },
    {
      "id": 2,
      "name": "样式和主题",
      "description": "实现success、warning、error、info四种类型的样式",
      "status": "pending",
      "priority": "high",
      "category": "styling",
      "estimated_hours": 3,
      "dependencies": [1],
      "test_criteria": [
        "四种类型样式正确",
        "图标显示正确",
        "颜色符合设计规范"
      ]
    },
    {
      "id": 3,
      "name": "关闭功能",
      "description": "添加可关闭按钮和自动关闭功能",
      "status": "pending",
      "priority": "medium",
      "category": "feature",
      "estimated_hours": 2,
      "dependencies": [1],
      "test_criteria": [
        "点击关闭按钮可关闭Banner",
        "自动关闭定时器正常工作",
        "触发onClose回调"
      ]
    }
  ]
}
```

**功能清单设计原则**:
- 🎯 **原子化**: 每个功能1-3小时可完成
- 🔗 **依赖明确**: 通过dependencies字段声明
- ✅ **可验证**: test_criteria具体可测
- 📊 **优先级**: high/medium/low

---

### 步骤3: 获取开发任务

```bash
# 获取下一个任务（自动选择优先级最高、依赖已满足的功能）
python3 cursor-autonomous-coding/scripts/next_task.py \
  --component pep-common-banner \
  --save

# 输出示例：
# ===== 下一个开发任务 =====
# 
# 功能 #1: 基础组件结构
# 优先级: high
# 预计时间: 2小时
# 
# 描述:
# 创建Svelte组件基础结构，包含props定义和基本样式
# 
# 验收标准:
# - 代码通过TypeScript检查
# - 组件可正常导出
# 
# 测试标准:
# - 组件可以被导入
# - 接受type、title、message props
# - 渲染正确的HTML结构
# 
# ⚠️ 提示词已保存到: components/pep-common-banner/.component-dev/current_prompt.md
```

**自动选择逻辑**:
1. 状态为 `pending` 的功能
2. 依赖的功能都已 `completed`
3. 按优先级排序：high > medium > low
4. 同优先级按ID排序

---

### 步骤4: 在Cursor中开发

```bash
# 1. 打开提示词文件
cat components/pep-common-banner/.component-dev/current_prompt.md

# 2. 复制全部内容

# 3. 在Cursor IDE中粘贴给AI

# 4. 根据AI的建议开始编码
```

**最佳实践**:
- 💬 **明确沟通**: 告诉AI你的具体需求
- 🔄 **迭代开发**: 先实现核心功能，再优化
- ✅ **边开发边测试**: 随时验证功能
- 📝 **记录问题**: 遇到的问题和解决方案

**Cursor中的典型对话**:

```
你: [粘贴提示词]

AI: 我将帮你创建 pep-common-banner 组件的基础结构...
    [生成代码]

你: 看起来不错，但是type prop应该是联合类型

AI: 好的，我修改为 type: 'success' | 'warning' | 'error' | 'info'
    [更新代码]

你: 完美！现在添加基础样式

AI: [生成样式代码]
```

### 步骤5: 开发完成后验证

```bash

# 2. 本地预览
pnpm --filter pep-common-banner dev

pnpm --filter pep-common-banner type-check

# 4. 检查是否符合全局规则

  --component pep-common-banner
```

---

### 步骤6: 标记功能完成

```bash
# 标记功能 #1 完成
python3 cursor-autonomous-coding/scripts/mark_done.py \
  --component pep-common-banner \
  --feature-id 1

# 输出:
# ✅ 功能 #1 "基础组件结构" 已标记为完成
# 📝 请确保代码已提交到Git
```

**自动更新**:
- ✅ `features.json` 中的状态 → `completed`
- ✅ 记录完成时间
- ✅ 更新 `DEVELOPMENT.md` 日志

---

### 步骤7: 提交代码

```bash
# 提交代码
git add components/pep-common-banner/
git commit -m "feat(pep-common-banner): 实现基础组件结构

- 创建Svelte组件文件
- 定义type、title、message props
- 添加基础TypeScript类型
- 实现基础渲染逻辑

Closes #1"

# 推送到远程
git push origin feature/pep-common-banner
```

**提交规范**:
- 📝 使用约定式提交格式
- 🔗 关联功能ID
- 📋 列出具体改动
- ✅ 通过CI检查

  --component pep-common-banner \
  --count 3

## 🎯 最佳实践

### 1. 功能粒度

✅ **好的粒度** (1-3小时):
```json
{
  "id": 1,
  "name": "基础组件结构",
  "estimated_hours": 2
}
```

❌ **粒度太大** (需拆分):
```json
{
  "id": 1,
  "name": "完成整个组件",
  "estimated_hours": 20  // 太大了！
}
```

### 2. 依赖关系

✅ **清晰的依赖**:
```json
{
  "id": 3,
  "name": "高级动画",
  "dependencies": [1, 2]  // 依赖基础结构和样式
}
```

❌ **循环依赖** (避免):
```json
// 功能1依赖功能2，功能2又依赖功能1 ❌
```

### 3. 测试标准

✅ **具体可验证**:
```json
"test_criteria": [
  "点击按钮后背景色变为红色",
  "disabled状态下点击无效",
  "触发onClick回调，参数正确"
]
```

❌ **模糊不可验证**:
```json
"test_criteria": [
  "功能正常",
  "没有bug"
]
```

### 4. 提交规范

✅ **好的提交信息**:
```bash
git commit -m "feat(pep-common-banner): 实现基础组件结构

- 创建Banner.svelte组件
- 定义props: type, title, message
- 添加TypeScript类型定义
- 实现基础渲染逻辑

Closes #1"
```

❌ **差的提交信息**:
```bash
git commit -m "update"  # 太简单
git commit -m "修复bug"  # 不清楚修了什么
```

## 🐛 常见问题

### Q1: 功能太多，从哪个开始？

**A**: 使用 `next_task.py`，它会自动选择：
1. 优先级最高的
2. 依赖已满足的
3. 状态为pending的

```bash
python3 scripts/next_task.py --component xxx --save
```

### Q2: 多个功能可以同时开发吗？

**A**: 如果功能之间**没有依赖关系**，可以：

```bash
# 方案1: 同一分支，按顺序开发
git checkout -b feature/pep-common-banner

# 方案2: 不同分支，并行开发（高级）
git checkout -b feature/pep-common-banner-styles
git checkout -b feature/pep-common-banner-close
```

### Q3: 功能做到一半想切换怎么办？

```bash
# 1. 保存当前进度
git stash save "WIP: 样式开发到一半"

# 2. 获取新任务
python3 scripts/next_task.py --component xxx --save

# 3. 开发新任务...

# 4. 恢复之前的进度
git stash pop
```

### Q4: features.json 被我改乱了怎么办？

```bash
# 验证并自动修复
python3 scripts/validate.py --component xxx --fix

# 如果无法修复，从Git恢复
git checkout -- components/xxx/features.json
```

### Q5: 如何跟其他组件协作？

每个组件独立开发，通过monorepo的依赖管理：

```json
// components/pep-modal/package.json
{
  "dependencies": {
    "pep-common-banner": "workspace:*"  // 依赖其他组件
  }
}
```

```bash
# 其他组件发布后，更新依赖
pnpm install
```
